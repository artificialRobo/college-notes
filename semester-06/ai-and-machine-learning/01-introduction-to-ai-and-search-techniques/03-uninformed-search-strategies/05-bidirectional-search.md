# Bidirectional Search

## Definition

**Bidirectional Search** is an **uninformed search algorithm** that performs **two simultaneous searches**: one forward search from the **initial state** and one backward search from the **goal state**. The search terminates when the two searches meet at a common node.

Instead of searching from only the start node, Bidirectional Search reduces the search space by exploring from **both directions simultaneously**.

**Core Idea:** Search forward from the start and backward from the goal until the two searches meet.

## Key Characteristics

- **Search type:** Uninformed search
- **Expansion strategy:** Simultaneous forward and backward search
- **Data structures used:** Two queues (for BFS) or two priority queues (for UCS)
- **Completeness:** Yes (under appropriate conditions)
- **Optimality:** Yes (when both searches use BFS with equal step costs)

## Working Principle

Bidirectional Search begins with:

- a **forward search** from the initial state,
- a **backward search** from the goal state.

Both searches expand nodes level by level. The algorithm stops when a node generated by one search has already been generated by the other search.

### Algorithm Steps

1. Initialize two frontiers:
   - Forward frontier from the start node.
   - Backward frontier from the goal node.
2. Expand one level in the forward direction.
3. Expand one level in the backward direction.
4. Check whether the two frontiers intersect.
5. If an intersection is found, combine the two paths to obtain the solution.
6. Otherwise, continue the search.

## Bidirectional Search Algorithm (Pseudo Code)

```text
BidirectionalSearch(start, goal):

    create forward frontier
    create backward frontier

    while both frontiers are not empty:

        expand forward frontier

        if intersection found:
            return solution

        expand backward frontier

        if intersection found:
            return solution

    return failure
```

## Example

Consider the following search graph:

```text
A — B — C — D — E — F — G
```

Suppose:

- **Start node = A**
- **Goal node = G**

### Forward Search

```text
A -> B -> C -> D
```

### Backward Search

```text
G -> F -> E -> D
```

The searches meet at **D**.

### Solution Path

```text
A -> B -> C -> D -> E -> F -> G
```

The search terminates as soon as the intersection occurs.

## State Space Exploration

### Forward Frontier

| Level | Nodes |
| --- | --- |
| 0 | A |
| 1 | B |
| 2 | C |
| 3 | D |

### Backward Frontier

| Level | Nodes |
| --- | --- |
| 0 | G |
| 1 | F |
| 2 | E |
| 3 | D |

Intersection occurs at **D**.

## Why Bidirectional Search is Efficient

Suppose:

- branching factor = **b**
- solution depth = **d**

A normal BFS explores approximately:

**O(b^d)**

nodes.

Bidirectional Search explores approximately:

**O(b^(d/2) + b^(d/2))**

which is much smaller than **O(b^d)**.

For large search depths, this results in a significant reduction in the number of explored nodes.

## Time and Space Complexity

Let:

- **b** = branching factor
- **d** = depth of the solution

### Time Complexity

```text
O(b^(d/2))
```

### Space Complexity

```text
O(b^(d/2))
```

This is substantially better than BFS for large values of **d**.

## Properties of Bidirectional Search

| Property | Bidirectional Search |
|----------|----------------------|
| Complete | Yes |
| Optimal | Yes (with BFS and equal costs) |
| Time Complexity | O(b^(d/2)) |
| Space Complexity | O(b^(d/2)) |
| Data Structures | Two Queues |
| Search Direction | Forward and backward |

## Advantages of Bidirectional Search

- Reduces the search space significantly.
- Faster than BFS for large search depths.
- Can find optimal solutions with BFS.
- Useful for shortest-path problems.
- Efficient when the goal state is explicitly known.

## Disadvantages of Bidirectional Search

- Requires knowledge of the goal state.
- Backward search may not be possible in all problems.
- Intersection detection can be computationally expensive.
- Requires additional memory for maintaining two frontiers.

## Conditions for Bidirectional Search

Bidirectional Search works effectively when:

- the goal state is known,
- reverse operators are available,
- the state space is reversible,
- both searches can be performed efficiently.

## Applications of Bidirectional Search

Bidirectional Search is used in:

- Route finding and navigation systems
- Shortest-path problems
- Network routing
- Social network analysis
- Puzzle solving
- State-space search problems

## Bidirectional Search vs BFS

| BFS | Bidirectional Search |
|-----|----------------------|
| Searches from start only | Searches from both start and goal |
| Explores O(b^d) nodes | Explores O(b^(d/2)) nodes |
| Uses one queue | Uses two queues |
| Simpler implementation | More complex implementation |
| Higher search time | Lower search time |

## Limitations

Bidirectional Search is not suitable when:

- the goal state is unknown,
- reverse actions cannot be generated,
- the state space is irreversible,
- maintaining two frontiers becomes expensive.

## Conclusion

**Bidirectional Search** is an uninformed search algorithm that performs **simultaneous forward and backward searches** from the start and goal states. The search terminates when the two frontiers meet. It uses **two queues** and has **time complexity O(b^(d/2))** and **space complexity O(b^(d/2))**. Bidirectional Search is **complete and optimal** for equal step costs and is widely used in **shortest-path and route-finding problems** because it significantly reduces the search space compared to Breadth-First Search.
